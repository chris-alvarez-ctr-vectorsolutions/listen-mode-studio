# Validity pass and lint checklist

Stage 6 runs every check below and reports pass or fail, with the line and a fix for each failure. Starting targets are marked; tune them by ear after a few modules.

## A. Facts (validity)

- [ ] Every claim-bearing line maps to a ledger ID in the trace table.
- [ ] No claim is added to, strengthened, generalized or combined.
- [ ] Every example list appears in the source content or the ledger.
- [ ] No statistic, date, count or source appears that the ledger doesn't hold.
- [ ] Flagged claims are marked and used only as the ledger allows.
- [ ] No host or character moment carries a fact, injury, exposure or outcome.
- [ ] No real company is named as an employer.
- **Any new fact:** list it for the SME with the line it came from. Don't cut it silently.

## B. Modular rules

- [ ] The open only promises content from positions that play in every listen.
- [ ] No part refers to another part ("again," "earlier," "like we said").
- [ ] Each Harder version stands alone.
- [ ] Each add-on sits before its part's ending and doesn't re-introduce anyone.
- [ ] There are no bridges, and each part's first exchange names its topic plainly.
- [ ] Each quick take has its own open and close line and never refers to the listen.

## C. Learning

- [ ] Each part serves one objective and carries its required claims.
- [ ] Each Know part restates the core rule once, near the end.
- [ ] Feel parts don't instruct. Perceive parts don't tell the listener what to do.
- [ ] Any judgment hold asks a question that tests that part's objective.
- [ ] Every learning outcome in the analysis (if provided) maps to at least one part.

## D. Uncanny-valley lint

| Check | Starting target |
| --- | --- |
| Ray's share of words in an expert part | About two-thirds |
| Dana restatements per part | One at most |
| Echo exchanges ("Not the bench." / "Not the bench.") per part | One at most |
| Each way in and way out | Used once per listen |
| "Solid advice," "Any final thoughts?" and other stock host lines | Once per listen each |
| Average sentence length | Under about 15 words, with a mix of short and long |
| Sentences over 20 words | None in dialogue |
| Concrete, visual details per part | At least one |
| Light or funny moments per part | One at most |
| Delivery tags per part | Two to four |
| CAPS emphasis per part | One or two words |
| Em dashes | None |

## E. Conversation

- [ ] The open has no scene, no character and no host background, and stays under 60 words.
- [ ] No speaker has more than two lines in a row (a character telling their own story is exempt).
- [ ] Every setup has its payoff in the same part. No "hold onto that picture."
- [ ] Ray's background comes up only when Dana asks, or as an aside backing a point.
- [ ] No characters are mentioned outside their own part.
- [ ] No example wording from the production guide, lint checklist or pattern library appears in the script.
- [ ] Every answer is a full spoken sentence; fragments appear only as reactions.
- [ ] Each speaker uses a light filler or softener once or twice per part, not in every line.
- [ ] Every question from Dana connects to Ray's previous answer.
- [ ] Nothing ("the shortcut," "that rule") is referred to before it's been introduced.
- [ ] Every scenario Ray describes is framed ("Let's say...") and flows as one or two linked sentences.
- [ ] Read aloud, every line sounds like something a person would say out loud.

## F. Length

- [ ] Each asset is inside its word range in the production guide.
- [ ] Runtime is reported for each part and each listen (words / 140, plus holds and stings).
